# Публикация «Сметочка» в Google Play

Краткий чеклист для первого релиза в [Google Play Console](https://play.google.com/console).

## 1. Подпись приложения (обязательно)

Release-сборка **не должна** подписываться debug-ключом. Создайте upload keystore **один раз** и храните его в безопасном месте (без keystore нельзя обновлять приложение в том же listing).

```bash
cd android
keytool -genkey -v \
  -keystore upload-keystore.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias upload
```

Скопируйте шаблон и заполните:

```bash
cp key.properties.example key.properties
# Отредактируйте пароли и путь storeFile
```

Файлы **не коммитить**: `key.properties`, `*.jks`, `*.keystore` (уже в `.gitignore`).

## 2. Сборка AAB для магазина

Google Play принимает **Android App Bundle** (`.aab`), не APK.

```bash
flutter pub get
flutter build appbundle --release
```

Готовый файл:

`build/app/outputs/bundle/release/app-release.aab`

Проверка на устройстве (опционально):

```bash
flutter build apk --release
flutter install --release
```

## 3. Версия приложения

В `pubspec.yaml`:

```yaml
version: 1.0.0+1
```

- `1.0.0` — `versionName` (видит пользователь)
- `1` — `versionCode` (целое, **увеличивать** при каждой загрузке в Play)

Пример следующего релиза: `1.0.1+2`.

## 4. Идентификатор пакета

`applicationId`: `com.remontestimate.remont_estimate`

После публикации **менять нельзя** — это новое приложение в каталоге.

## 6. Безопасность данных (Data safety)

Укажите в анкете Play Console примерно так:

- **Сбор данных**: нет / данные не передаются разработчику
- **Шифрование при передаче**: не применимо (нет серверной передачи)
- **Данные на устройстве**: сметы, фото материалов — локально, по действию пользователя
- **Разрешения**: камера и галерея — для фото материалов; сохранение в галерею — по запросу пользователя

Приложение **не использует** сеть для своей логики; сторонние SDK (шаринг, открытие файлов) могут открывать системные диалоги.

## 7. Разрешения Android

| Разрешение | Зачем |
|------------|--------|
| `CAMERA` | Съёмка фото материалов |
| `READ_MEDIA_IMAGES` | Выбор фото из галереи (Android 13+) |
| `READ_EXTERNAL_STORAGE` | Галерея на Android ≤12 |

Камера помечена как **необязательная** (`required=false`) — приложение работает без камеры, только с галереей.

## 8. Тестирование перед продакшеном

1. Internal testing — загрузить AAB, добавить тестовый аккаунт.
2. Проверить: экспорт PDF/Excel, фото, тёмная тема, смена языка, сохранение в галерею.
3. Production — после проверки internal/closed testing.

## 9. Play App Signing

При первой загрузке включите **Google Play App Signing** (рекомендуется): Google хранит ключ подписи для пользователей, вы загружаете AAB, подписанный upload key.

Сохраните **upload certificate** и пароли keystore в менеджере паролей.

## 10. Частые ошибки

### `Given final block not properly padded` при подписи

Неверный **storePassword** или **keyPassword** в `android/key.properties` (или опечатка при создании keystore).

Проверка (подставьте свои пароли):

```bash
keytool -list -v -keystore android/upload-keystore.jks -alias upload
```

Если команда падает — пароль хранилища неверный. После успешного `-list` сборка должна пройти, если `keyPassword` в `key.properties` совпадает с паролем ключа.

В `key.properties` обычно **один и тот же** пароль в `storePassword` и `keyPassword`, если при `keytool` вы дважды вводили одно значение.

- Загрузили APK вместо AAB → используйте `flutter build appbundle`.
- `versionCode` не увеличили → Play отклонит обновление.
- Потеряли `upload-keystore.jks` → нельзя обновить то же приложение (только новый package name).
- Release подписан debug-ключом → создайте `key.properties` и пересоберите.
